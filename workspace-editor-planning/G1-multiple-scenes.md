# G1 — Multiple scenes open & editable at once (DocumentContext + 3D world isolation)

**Effort:** XL · **Upstream dependency:** none (this is the foundation) · **Downstream:** G2, G3 (hard); G4, G5 (soft)

## Approach

Promote `EditorData` from a single `current_edited_scene` index over `Vector<EditedScene>` to **N permanently-live `DocumentContext`s**, each owning its own `SubViewport` with `set_use_own_world_3d(true)` (own World3D + World2D + scenario), an `EditorSelection`, an `EditorSelectionHistory`, the root `Node`, path/type, and the existing per-scene undo-redo `history_id`. `EditorNode`'s single `scene_root`, `editor_selection`, and `editor_history` are demoted to **delegating accessors** that resolve the active document, so the ~300 existing call sites keep compiling and auto-follow. Scene switching becomes cheap **activate/deactivate** (visibility + dock re-point), not node reparenting.

The make-or-break gate is a **throwaway own-World3D isolation SPIKE done FIRST**: two own-World3D `SubViewport`s rendering two scenes side-by-side with manually-routed gizmo instances, per-world picking, and zero bleed. If it fails, fall back to a single-live-3D-pane model and reassess **before** any refactor.

For v1, keep `Node3DEditor`/`CanvasItemEditor` and the docks as **singletons that rebind** on active-document change; route every hard-coded 3D scenario/world/space-state call through **one bound-document helper** so the later per-pane-instancing switch is a mechanical substitution. True simultaneous side-by-side 3D rendering and per-pane editor instances are deferred to G2.

## Ordered steps

1. **SPIKE: prove own-World3D isolation (throwaway, gates the whole goal, do FIRST).** Build a temporary EditorPlugin/debug action with two side-by-side `SubViewportContainer`→`SubViewport`, each `set_use_own_world_3d(true)` (viewport.h:883), each parenting a different loaded scene root + own Camera3D. Manually instance a mesh via `RenderingServer::instance_create2` into EACH `viewport->get_world_3d()->get_scenario()` (mimic `node_3d_editor_plugin.cpp` gizmo/grid/origin instancing). **Prove all of:** (a) each viewport shows only its own mesh+gizmo, zero bleed; (b) a Node3D under an own-world SubViewport reports `find_world_3d()==that world` so visual instances auto-register into the correct scenario; (c) per-world picking via `world->get_direct_space_state()` is isolated; (d) camera/grid in one doesn't affect the other. **Exit criterion:** two independently-rendered, independently-pickable 3D scenes on screen at once. Throw the code away.
2. **Define `DocumentContext` class and ownership model.** Owns: `SubViewport* scene_root` (own World3D + World2D, mirrors `editor_node.cpp` scene_root config 478-566 but drops/conditionalizes `set_disable_3d`); `Node* root`; `EditorSelection*`; `EditorSelectionHistory`; `int history_id` (reuse editor_data.h:123); `String path`; `enum Type {SCENE_2D,SCENE_3D,SCENE_MIXED,SCRIPT,RESOURCE}`; `Dictionary editor_states`. Methods: world/scenario/selection/history accessors, `activate()/deactivate()` (visibility + audio-listener handoff, **NO node reparenting**), `serialize/deserialize`. Owned by `EditorData`; freed on close (memdelete selection, RS::free_rid owned instances).
3. **Promote `EditorData` to N live documents.** editor_data.h:113-144: each `EditedScene` OWNS a `DocumentContext*`. `current_edited_scene` becomes the active/focused index; `add_edited_scene` eagerly constructs a DocumentContext+scene_root SubViewport; `remove_scene` tears it down. Make `save/restore_edited_scene_state` and the `get_edited_scene_root/set_edited_scene/get_scene_path` family document-scoped. Add `get_document/get_active_document/document_count`.
4. **Demote `EditorNode` single scene_root/selection/history to delegating accessors.** Stop creating the single global `scene_root` and `editor_selection`; parent each DocumentContext's scene_root under the scene-root-tree container. Make `get_scene_root()/get_editor_selection()/get_editor_selection_history()` (editor_node.h:802-803) delegate to the active DocumentContext with **no caching**. Rewrite `_set_current_scene_nocheck` (4698) and `set_edited_scene_root` (4584) into `_activate_document(idx)`: drop the remove_child/add_child reparent churn (4717-4734); activation only flips visibility + re-points docks/main-screen + sets `get_tree()->set_edited_scene_root` to the FOCUSED doc only.
5. **Route 3D scenario/world/space-state through ONE bound-document helper.** node_3d_editor_plugin.cpp: replace all 11 `get_tree()->get_root()->get_world_3d()->get_scenario()` sites (gizmos 4712-4773, origin 8327, grid 9066) and `get_direct_space_state()` picks (5356, 9357) with a single helper resolving the bound DocumentContext's scenario/world. Add a `DocumentContext*`/`Ref<World3D>` member + `bind_document()` to `Node3DEditorViewport`; call `viewport->set_world_3d(doc world)` on the SubViewport at 6663 and re-point on switch (edit 7742, Plugin edit/make_visible 11053/11040). selection-box (7398-7421) and per-node gizmos (node_3d_editor_gizmos.cpp:216) become correct once nodes live under an own-world SubViewport — verify only. Add `Node3DEditor::set_active_world` that re-instances editor gizmo/grid/origin into the new scenario.
6. **Route 2D World2D + bind docks to the active document.** canvas_item_editor_plugin.cpp:5654: reparent the **ACTIVE** document's scene_root (not a global one) into the editor's SubViewportContainer; re-point on switch. 2D isolation comes largely free from each doc's own World2D (verify set_world_2d wiring, get_edited_scene_root callers 459/703). Decouple "which world the camera renders" from "which SubViewport owns the nodes." Keep SceneTreeDock/InspectorDock singletons for v1 but define+call a **rebind API** on activation: `SceneTreeDock::set_edited_scene(doc->root)` + point at `doc->selection`; InspectorDock update. `_edit_current` (3110) routes through the document-scoped accessor. **This rebind API is the exact seam G3 extends into instance-per-pane.**
7. **Minimal side-by-side two-document proof.** Bind at least two `Node3DEditorViewport`s (or two `SubViewportContainer`s) to two DIFFERENT document worlds via the per-viewport `set_world_3d` from step 5. Explicitly flag the single-`Node3DEditor`-rebind model as tech debt blocking true simultaneous side-by-side 3D until per-pane instancing (G2).
8. **Activation, undo/redo, title/tabs, session restore, persistence.** Verify `EditorUndoRedoManager` keys by each DocumentContext's stable `history_id` (~4741). Update `_update_title/_set_main_scene_state/_get_main_scene_state` and `EditorSceneTabs` to reflect "active document." Make session-restore/project-load instantiate a DocumentContext per saved scene. Ensure `_update_from_settings` (478-566) applies viewport settings to ALL documents' scene_roots. On close, free each DocumentContext with no RID leaks; consider lazy realization / process+physics suspension of non-visible background documents.

## Conflicts & resolutions

- **DocumentContext placement (modules/ vs editor/).** Plan A edits editor/ freely; Plan B aspires to confine code to modules/. **Resolution:** editor/ placement — DocumentContext owns editor-only types and is consumed pervasively, so it cannot live in modules/. The editor/-stock constraint cannot survive G1 (this is a core refactor, not a plugin). **Action:** surface as a required constraint renegotiation (open issue); track every editor/ change as a documented fork patch concentrated behind single helpers.
- **De-singletonization scope: rebind vs per-pane instances.** **Resolution:** ship singleton-rebind for v1 (correct context for the focused pane + a minimal two-viewport side-by-side proof); assign per-pane instancing to **G2**, not G1. **Tech debt:** single-rebind renders only one fully-live 3D pane at a time. **Migration path:** funnel all scenario/world resolution through ONE helper + a per-viewport world member now, so the v1→per-pane switch is mechanical.
- **EditedScene folded vs composed.** **Resolution:** each EditedScene **OWNS** a `DocumentContext*` (composition) for v1 — minimizes blast radius across the 76 EditorData accessors. Full folding is a later cleanup.
- **2D rendering model: reparent nodes vs bind world only.** **Resolution:** reparent the ACTIVE document's own scene_root SubViewport into the 2D editor container and rely on its own World2D — no per-node reparenting, no manual 2D scenario routing. Decouple camera-world from node-ownership so a node is never in two viewports.

## Risks

- Penetrating high-risk 3D/2D editor singleton world wiring across ~6 large files while auditing 300+ singleton/global call sites; the own-World3D SPIKE (S/M) gates everything.

## Cross-goal dependencies

- **G2** depends on DocumentContext as the unit each tab/pane hosts; full simultaneous side-by-side + true per-pane Node3DEditor/CanvasItemEditor instancing lands there.
- **G3** depends on the dock-rebind API (set_edited_scene + selection pointer); G1 ships singleton-rebind, G3 swaps it for instance-per-pane without touching EditorData.
- **Script/resource tabs** reuse the active-document accessor + the Type enum (SCRIPT/RESOURCE); G1 must define the enum.
- **Layout persistence / multi-window** uses `DocumentContext::serialize/deserialize` + existing EditorDockManager prior art.
- G1 has no upstream dependency — it is the foundation — but MUST define the DocumentContext shape, the dock-rebind seam, and the single scenario/world helper all downstream goals consume.
